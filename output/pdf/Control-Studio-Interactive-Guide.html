Three keys. Different jobs.

You do not need every credential on day one. Start with the workspace token; add a provider key when you want a real AI answer.

Workspace token

Opens the studio.
Your local owner token connects this app to your workspace. In this installation, find it in %LOCALAPPDATA%\ControlStudio\workspace-token.txt. Paste it into Workspace token and click Connect workspace.

Provider API key

Connects the model.
Get a key from your OpenAI, Anthropic or Gemini provider account. Save it under Workspace → Access & settings → Provider credentials. A chat subscription is separate from an API key.

Scoped API token

Connects your own app.
Create an expiring token under API credentials. Give it only the environments, resources and role your integration needs. Copy its one-time value into your app’s protected server environment.

What you should see

The experiment analysis shows sample sizes, confidence and whether evidence is conclusive.

  1. 1

Self-hosted deployment, backup and recovery

Location: compose.production.yaml and scripts/recovery.mjs.

Production stack and recovery

docker compose -f compose.production.yaml up -d --build
# Open http://localhost:8080 after startup.

node scripts/recovery.mjs snapshot data NEW_SNAPSHOT
node scripts/recovery.mjs restore SNAPSHOT NEW_DATA
# Stop the server before switching its data directory.
What you should see

The service is healthy, data persists, and a restore into a new directory validates.

  1. 1

    Run npm ci/npm start with Node 24.14-24.x for development. For Docker set persistent STUDIO_ADMIN_TOKEN and run docker compose -f compose.production.yaml up -d --build; open localhost:8080.

  2. 2

    For a real server configure domain/DNS/ports and exact STUDIO_PUBLIC_ORIGIN. Production-style Docker uses same-host workers, persistent volumes, Caddy, health checks, read-only app filesystem and bounded logs; it is not multi-region HA.

  3. 3

    Snapshot database plus vault key using recovery.mjs snapshot DATA NEW_DIRECTORY. Protect off-host copies. Restore into a new directory with recovery.mjs restore SNAPSHOT NEW_DATA_DIRECTORY, stop the old server, verify data and switch volumes. Checksums detect corruption, not malicious replacement.

When something does not work.

Site cannot be reached

The local server is stopped. From the project folder run npm start. Reuse your existing FLAG_ADMIN_TOKEN when restarting; then open http://127.0.0.1:4315/.

No completion generated

Resolve is a selection preview. To generate text, save a provider key, choose a valid provider/model, save the configuration, and explicitly allow provider calls in Test.

401 or disconnected

Reconnect with a valid workspace token or sign in again. Check credential expiry and whether the server token changed after a restart.

403 or a disabled action

Check role, environment, resource scope and execution policy. An operator cannot edit production; production changes can require an independent reviewer.

Version conflict or stalled job

Refresh the current resource before saving. For a queued job, inspect worker state and provider errors before retrying or resuming.

Provider error or unknown cost

Check the returned error, account quota, API key, model ID and parameters. Unknown token usage or missing configured prices means unknown cost, not free usage.

  1. 1

  3. 3
